## 1. 目标行为（对齐 Shimeji）

Shimeji 的动作表里，四个方向是**并列**的，不是"地面 + 特例"：

| 状态 | 表现 |
| --- | --- |
| 地面 | 在屏幕底部左右走（已有） |
| 沿左墙 / 沿右墙 | 贴住屏幕左右边缘，上下移动 |
| 沿天花板 | 贴住屏幕顶部，横向移动 |

玩家的动作序列大致是：在地面走到屏幕边缘 → 吸附到墙上 → 沿墙往上爬 → 爬到顶端吸附到
天花板 → 沿天花板横移 → 从另一侧下来。任何时候被拖拽/投掷都会打断攀爬、掉回地面。

## 3. 核心方案：`Surface` 依附面（已落地，见 §9）

### 3.1 先纠正一个错误

本文初稿写的方案是"把坐标系转一下、`physics.py` 一行不改"。**这是错的**，动手前才发现：

- **地面是承压**：重力把宠物压向表面，所以宠物"站"在上面；
- **天花板和墙面是吸附**：重力把宠物**拉离**表面，宠物靠**抓握**留在上面。

两者是镜像关系。而任何刚体旋转都会**把重力的方向一起转**——把天花板转成规范坐标里的"地面"
之后，重力在规范坐标里指向背离支撑边，`step()` 的"重力朝 `bounds.bottom`"就直接算反了。
所以"零改动复用"这条路走不通，必须让物理知道"这个宠物是靠抓握留住的"。

### 3.2 实际做法

两件事就够，都不需要新的运动代码：

**(a) 吸附 = 零厚度的 `Bounds`。** `step()` 本来就会把状态吸附到 `bounds.bottom` 且不许出框。
把矩形压成零厚度，"不许出框"立刻变成"钉在一条线上、可以沿线滑动"：

| Surface | `surface_bounds()` 的结果 | 效果 |
| --- | --- | --- |
| `FLOOR` | 原样返回 | 站立（现状） |
| `CEILING` | 零高（`bottom = top`） | 钉住 `y`，可沿 `x` 走 |
| `WALL_LEFT` | 零宽（`right = left`） | 钉住 `x`，可沿 `y` 爬 |
| `WALL_RIGHT` | 零宽（`left = right`） | 钉住 `x`，可沿 `y` 爬 |

这和栖息用的是同一个把戏（**换 `Bounds`，不动物理**），只是把"换个高度"推到了"压成一条线"。

**(b) 吸附期间跳过重力。** `Surface.clinging` 为真时 `step()` 不加 `gravity`，并把 `grounded`
视为真。后者是必须的：否则挂在天花板上的宠物永远不 `settled()`，物理循环会一直空转
（栖息那次已经踩过同一个坑）。抓着表面时的阻尼用 `ground_friction` 而不是 `air_drag`
——松手应该是"停下"，不是"滑翔一秒七"。

`drive_vy` 是这次唯一新增的驱动轴：地面上宠物永远只需要 `vx`，而爬墙必须能**向上**动。

```python
class Surface(str, Enum):
    FLOOR = "floor"
    CEILING = "ceiling"
    WALL_LEFT = "wall_left"
    WALL_RIGHT = "wall_right"

    @property
    def clinging(self) -> bool: ...      # 是否靠抓握而非承压
    @property
    def along(self) -> str: ...          # 沿面轴："x" 或 "y"
```

`MotionState.surface` 默认 `FLOOR`，所以既有代码一行不用改；`attach()` / `detach()` 负责
抓住与松手（`attach()` 顺手置 `grounded=True`，否则第一帧会误报一次落地）。

`MotionEvents` **没有新增字段**：爬到墙顶会触发既有的 `ceiling`，爬到底会触发既有的 `landed`，
窗口层靠这两个事件换面即可。


## 4. 吸附与脱离规则（放在 window 层，不进 physics）

物理只负责"在有支撑面的情况下怎么动"，"什么时候换支撑面"是玩法，属于窗口层：

- 在地面朝某一侧走到 `x == bounds.left / right` 且**继续朝该侧走** → 吸附到
  `WALL_LEFT` / `WALL_RIGHT`，从当前高度开始爬；
- 沿左墙爬到 `y == bounds.top` → 吸附 `CEILING`；沿右墙同理；
- 从墙上爬回 `y == bounds.bottom` → 回到 `FLOOR`；
- **任何一次拖拽/投掷都打断攀爬**，恢复 `FLOOR` 重力自然下落；
- 换面时播放一次过渡动画（现在先复用 `climb`）。

> ⚠️ **待定**："墙上横向挪动"的具体含义。见 §7 第 2 条——它决定墙上要不要给一条可攀附的**带**
> （而不是一条线），以及是否需要在墙上支持横向驱动。
> **已落地的版本**取的是"墙 = 零宽的一条线"：宠物只能沿墙上下爬，横向那轴被 `surface_bounds()`
> 钉死，既不能主动内移、也就谈不上"内移即脱离"。物理地基对 A/B 两种读法都已支持
> （`clinging` 跳过重力 + `drive_vx`/`drive_vy` 两轴驱动），所以只差把 `_effective_bounds()`
> 里墙面那一支由"零宽矩形"换成"带宽矩形"、再补上横向驱动判据。

## 7. 决策点

1. ~~做不做、以及素材怎么办~~ → **已定：不等素材，先打通逻辑。** 回退链已落地（§5）。
2. **墙上的自由度 —— 唯一还没定的。** 琰 的答复是"允许墙上横向挪动"，但这句话有两种读法，
   而它们对窗口层的要求不同：

   | 读法 | 行为 | 窗口层要做什么 |
   | --- | --- | --- |
   | **A. 挪开即脱离** | 墙上是一条线。朝屏幕内侧（离开墙的方向）移动 → 立刻脱离、开始下落 | 判"驱动方向是否背离表面"，是则 `detach()`，矩形用零宽 |
   | **B. 墙是一条可攀附的带** | 屏幕边缘有一条带宽（比如 60px），带内重力挂起、可上下左右自由爬；爬出带外才掉落 | 矩形给成**带**（不是零宽），重力挂起但两轴都自由；出带即 `detach()` |

   两种读法物理地基都已支持（`clinging` 跳过重力 + `drive_vx`/`drive_vy`），差的只是
   `_active_bounds()` 给什么矩形、以及脱附判据。**当前落地的是第三种、最小的一种**：墙 =
   零宽的一条线，横向轴被钉死，宠物只能上下爬、在两端换面——它同时满足 A 和 B 的"上下爬"部分，
   但没有横向自由度。**需要琰确认是 A、B，还是就保持现在这样。**
3. ~~屏幕边缘的范围~~ → **已定：算。** 任务栏区域（`floor_offset_px`）与副显示器都算可攀附表面。
   注意这会牵动 `Bounds` 的定义：现在 `bounds_for()` 只认一个矩形，多显示器需要每个屏幕一个。

## 9. 已落地的部分（`b063c72`）

```python
Surface            # floor / ceiling / wall_left / wall_right
                   #   .clinging  是否靠抓握（只有 floor 为假）
                   #   .along     沿面轴 "x" / "y"
surface_bounds()   # 把矩形压成零厚度：天花板零高、左右墙零宽 = 钉在一条线上
attach(state, s)   # 抓住：清零速度、置 grounded（否则第一帧误报落地）
detach(state)      # 松手：交还重力
step(..., drive_vx=None, drive_vy=None)   # drive_vy 是爬墙必需的新轴
```

关键实现细节，改这块之前先读：

- **吸附期间跳过重力，并且强制 `grounded = True`。** 后者不是为了好看，是为了让
  `settled()` 为真 —— 否则挂在墙上不动时物理循环会一直空转（栖息那次同款坑）。
- **吸附期间绝不能把 `y` 吸附到 `bounds.bottom`。** 那是地面逻辑；对爬到一半的宠物用会
  把它瞬移到地面。代码里这两条是同一个 `if clinging / else` 的两支。
- **抓着表面的阻尼用 `ground_friction`，不是 `air_drag`。** 用空气阻力的版本实测松手后
  还会滑行约 1.7 秒；抓握应该像摩擦。
- **`attach()` 必须置 `grounded=True`**，否则第一帧 `landed` 会误报一次（有专门一条测试
  记录这个反面例子）。

## 10. 窗口层落地（本次接线）

```python
_effective_bounds()      # surface_bounds(self._active_bounds(), self.surface)
_grip(surface, direction=...)   # 吸附 + 起爬；先 _leave_perch(fall=False) 保证与栖息互斥
_let_go()                # 松手，交还 FLOOR 重力
_advance_climb(before)   # 每 tick 扣减 stretch；到角先 _turn_corner()，否则续爬/松手
_reached_corner()        # 方向敏感：向上只认 top，向下只认 bottom
_pick_new_stretch()      # 换个方向续爬，但不许反身撞回刚站的那个角
_turn_corner()           # 墙顶→天花板（朝内）、墙底→落地、天花板两端→下墙
_drop_to_floor()         # 回地面：贴 bottom、清速度、播落地音
_grip_adjacent_wall()    # 地面走到屏幕边缘自动抓墙（perch 时不触发，否则会抓到屏幕边）
```

窗口层踩过的坑，比物理层还多：

- **`_reached_corner()` 必须方向敏感。** 最早写成"到 top 或到 bottom 就算到端"，
  结果从地面抓左墙（宠物本来就在 bottom）第一帧就判定"已到端" → 立刻掉回地面。
- **到角检查要每 tick 做，不能只在 `climb_remaining <= 0` 时做。** 否则一段很长的
  stretch 会一路把宠物顶进角落、贴着不动，永远等不到换面。
- **`_grip()` 的起始方向不能指向宠物已经站着的那个端。** 否则第一帧就翻角。
- **`return_idle` 定时器不能挂在攀爬动作上。** `play()` 里 `climb_wall_*` / `walk_ceiling`
  必须当作 looping 动作，否则爬两秒就被"动作结束回 idle"打断。
- **休息姿势统一由 `_rest_action` 一处算。** 站立 / 静坐（专注）/ 抓握三种"没事干时的样子"
  走同一个变量，`play(idle)` 解析到它；不然专注和攀爬会互相把对方的姿势冲掉。
  `CLING_REST_ACTIONS` 给出墙面→`climb`、天花板→`sit` 的映射。
